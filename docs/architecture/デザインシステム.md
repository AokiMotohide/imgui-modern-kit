# デザインシステム

[English](design-system.md) · [テーマ](テーマ.md) · [文書カタログ](../reference/文書カタログ.md)

デザインシステムは、Dear ImGuiの上で、制作ツールに共通のセマンティックトークン、アクセシビリティの公開経路、ホスト主導のデータビューを提供します。データ、状態、寿命はホストが持ち、ImKitは描画と要求の返却だけを行います。

現状: 以下の基盤は実装済みで、記録のとおり検証しています。次期リリースの仕様全体は受け入れていません。足りない部分は[残る実装](#残る実装)にあり、この文書が従来のEditor Suiteの検証を置き換えることはありません。

## テーマとトークン

```cpp
#include <imkit/theme.h>

// スキーム、コントラスト、密度からテーマを作る。
imkit::Theme theme = imkit::MakeTheme(imkit::ColorScheme::Dark,
                                      imkit::ContrastMode::Standard,
                                      imkit::Density::Comfortable);

theme.semantic.accent = ImVec4(0.2f, 0.6f, 1.0f, 1.0f); // トークンを変える
imkit::ResolveTheme(theme);                             // 描画用の射影を作り直す
```

- `MakeTheme(ThemePreset)` は13個のプリセットを作ります。`MakeTheme(scheme, contrast, density)` は基本のテーマを作ります。`MakePrecisionTheme` も引き続き使えます。
- `SetDensity` で、`Compact`、`Comfortable`、`Touch`（コントロールの高さ24、30、44 px）を切り替えます。文字の大きさは変わりません。
- 編集するのは `semantic`、`typography`、`radius`、`stroke`、`elevation`、`opacity` です。編集後に `ResolveTheme` を呼びます。従来の `colors` と `metrics` は、既存のエディタ用コードに向けた描画用の射影です。この2つを、別々に編集しないでください。
- ホストのフォントポインターを、ImKitが読み込んだり解放したりすることはありません。

| セマンティックトークン | 役割 |
|---|---|
| `canvas` | アプリケーションの最背面の背景 |
| `surface`、`surfaceRaised`、`overlay` | パネル、浮き上がったカード、ポップアップとダイアログ |
| `text`、`textSecondary`、`textDisabled` | 本文、補助、無効状態の文字 |
| `border` | 境界線と区切り線 |
| `accent`、`onAccent` | 主な操作と選択の色、その上に描く文字の色 |
| `success`、`warning`、`error` | 状態を示す色 |
| `control` | コントロールの状態別の色: rest、hover、pressed、focused、selected、disabled |
| `shadow` | 影の色 |

**コントラストとモーション**

- 標準コントラストでは、Dear ImGuiに射影する境界線の色は、`semantic.border` と面の色を混ぜて弱めた色です。そのため、枠線のコントラストが3:1を下回ることがあります。ハイコントラストでは、境界線を弱めません。
- `ValidateContrast` は、宣言した面とコントロールの状態に対し、アルファ合成を含めて、文字を4.5:1、フォーカスと境界線を3:1で確認します。境界線は、弱める前の `semantic.border` で測ります。任意のカスタム色、背景画像、合成後のすべてのウィジェット状態は、保証しません。
- `motion.reducedMotion` は、コンポーネントのアニメーションを止めます。`AnimationState` の補間は、Linear、EaseOut、EaseInOutです。

## アクセシビリティ

ホストが持つ `AccessibilityFrame` を、`ComponentOptions::accessibility` で渡します。

1. 描画の前に `Begin(generation)` を呼びます。
2. コンポーネントを描画します。
3. 描画の後に `Publish(sink)` を呼びます。

- ノードの文字列と子の配列は、その公開の間だけ借用します。保存領域があふれたときは、明示的に知らせます。
- `Validate()` は、ID、親、ラベル参照、循環を確認します。任意の診断で、大きなツリーに毎フレーム要求するものではありません。
- `ActionQueue` はホストが渡す固定領域を使い、アクセスはホストが直列化します。古い要求は、ホストが決めたフレーム境界で消してください。

**Windows UI Automation。** `IMKIT_BUILD_ACCESSIBILITY_WIN32` を有効にし、`imkit::accessibility_win32` をリンクします。

- `CreateWin32Provider` は、フレームをCOMスナップショットにコピーします。
- ホストは、COMを初期化し、`WM_GETOBJECT` を処理し、`QueryInterface` で `IRawElementProviderSimple` を取得し、`UiaReturnRawElementProvider` に渡し、呼び出し側が持つCOM参照を解放します。
- nativeクライアントはスナップショットを保持できるため、操作コールバックとそのユーザーデータは、スナップショットより長く生きている必要があります。
- スナップショットの更新、UIAイベント、アプリケーション終了時の無効化は、ホストの統合作業です。
- 実装済み: Invoke、Toggle、Focus、フラグメントのナビゲーション、共通プロパティ。ほかのUIAパターンは未実装です。

## ローカライズ

`LocaleContext` は、言語タグ、レイアウト方向、翻訳、数値と日時のコールバックを受け取ります。グローバルなロケールはありません。

- パンくずとデータ列の並びは、疑似RTLに対応します。双方向テキストの整形や、完全なRTLレイアウトではありません。
- 座標を扱うエディタのキャンバスは、方向を変えません。

## コンポーネントとデータビュー

`patterns.h` は、CommandPalette、SearchField、Breadcrumbs、SplitButton、Toolbar／ResponsiveToolbar、Dialog／AlertDialog、Popover、Menu、FormField、Progress、Spinner、Skeleton、空・読み込み・エラーの状態、ToastRegion、Pagination、AdaptiveSplitLayout、VirtualList、DataTable、TreeDataGridを公開します。

- 編集するデータとキューは、すべてホストが持ちます。描画関数は、要求を返すか、プロバイダの `apply` を同期的に呼びます。永続化とUndoは実装しません。
- プロバイダは、ソート、フィルター、ツリー展開の後の、平坦な可視インデックスを渡します。
- `query` はクリップした範囲を受け取ります。`id` と `cell` は、その範囲の中でだけ呼ばれます。行のIDは、安定した0以外の値にします。
- コールバックが返す文字列は、そのフレームの間、有効にしておきます。
- インデックスの再構築は、ホストがイベントで行います。描画の中で、全行を走査してはいけません。
- テーブルの選択イベントは、インデックスの範囲を持ちます。選択行ごとに確保せず、区間で選択を扱えます。
- 列幅と表示の切り替えは、Dear ImGuiのテーブルを使います。

## 残る実装

- すべての既存ラッパーのセマンティクス出力、複合部品の親・ラベル・操作の関係、すべてのUIAパターンとイベント、Galleryでの完全なUIA統合。
- ローヴィングフォーカスの網羅的な検証: disabledの項目、Tabsの閉じる操作とフォーカス復元、TreeとDataGridの完全なナビゲーションと先頭文字検索。
- FormFieldのラベルと検証のセマンティクス、不定進捗のアニメーション、レスポンシブなレイアウト方針、メニューとフォームのRTL、ホストの数値・日時の整形の利用。
- 部品の状態マトリクスの全数と、製品向けの個別パターンページ。長いラベルと狭い幅の受入。
- 既存のラスターアイコンの光学調整、サイズ別の光学的な受入、このAPI変更後のインストール済み・移設SDKの検証。

native OS/IME、実際のスクリーンリーダー、他アプリとの統合は未検証です。公開のImGui IOとnative backbufferのキャプチャは、これらの結果を示しません。

## 検証の記録

Editor Suite 2.0の基盤を入れた時点の記録です。アイコンの280個や、Comfortableの高さ28 pxなどの数値は、その時点のものです。

| 確認 | 結果 |
|---|---|
| Debug API | 既存の公開APIと、新しいデザインAPIのfixtureが、コンパイル・リンク・実行に成功 |
| テーマ | 12通りの組み合わせ、24／28／44 pxの密度、コントラスト、イージングとモーション低減のテストに合格 |
| セマンティックツリー | 安定したID、重複の検出、親、Grid／Row／Cellの関係、操作キューに合格 |
| Win32 UIA | 任意のターゲットがコンパイルでき、代表的な子・名前・Invokeコールバックの取得に成功 |
| 公開キーボードIO | Spaceでダイアログが開き、Escapeで閉じて、起動元にフォーカスが戻る |
| データビュー | DataTableとTreeDataGridの10万行: クリップしたクエリ、定常状態でのImGuiとC++のアロケーションは0 |
| アイコン | 280個のID、7段のラスター、アルファ・ティント・アトラスの対応、C++のアイコンテストに合格 |
| 外部のsource consumer | 別のホストImGuiターゲットで、MakeThemeとセマンティクスの公開をコンパイル・実行 |
| Release Gallery | ビルドに成功。2つの解像度でnative backbufferを100枚 |

キャプチャのディレクトリは、`out/design-system-final-1280` と `out/design-system-final-1920` です。4ページ×12テーマの96通りを2つの解像度で撮り、それぞれに日本語150%と疑似RTL 200%を加えています。代表的なフレームは目視で確認しました。キャプチャは、すべてのキーボード経路、状態マトリクス、アイコンの光学品質の証明ではなく、コミットもしません。
