# ImKit の仕組み

[English](how-it-works.md) · [文書索引](README.md) · [ユーザーガイド](guide.md)

ImKit は Dear ImGui の**上**に置かれ、隣にも置きません。ImKit を正しく使ううえで最も役に立つのは、Dear ImGui のフレームがどう動くか、そして**何が誰の所有か**という心智モデルです。このページではそのモデルを分かりやすく説明します。公式・権威的な所有・設計の参考は [アーキテクチャ](architecture.md) を参照してください。

## ImKit が何で、何でないのか

ImKit は C++20 静的ライブラリです。ImKit がする仕事は：

- Dear ImGui 独自のウィジェットを再利用し、テーマ付きバリエーションで拡張する（`imkit::imkit`）。
- 上位の複合部品を足す：ノードエディター、ビデオタイムライン、ワークフローパネル、アプリケーションの外装。
- 名前付きテーマ、アイコン集、デザインシステムのトークンモデルを提供する。

しない仕事：

- Dear ImGui コンテキスト、backend、レンダラ、フレームループの作成・所有。
- メディアのデコード・再生、シミュレーションの実行、アプリケーションデータの所有。
- 何かかの永続化。すべての状態はあなたのアプリに存在します。

この分離は意図的なものです。ImKit は Dear ImGui の仕組みを所有しないため、すでにコンテキストを持つアプリにそのまま落とせます。あなたの所有権、Undo、永続化のセミオティクスはそのままです。

## Dear ImGui のフレームがどう動くか

Dear ImGui は**即時モード**です。毎フレーム、アプリがインターフェース全体をゼロから再描画します。パターンは：

1. フレームループが `ImGui::NewFrame()` を呼び出します。
2. 任意の順序で描画コールを発出します。ImKit のコールはそれの延伸です。
3. `ImGui::Render()` を呼び、蓄積された描画を backend に渡します。
4. 次のフレームは、またゼロから始まります。

永続的なウィジェットツリーは存在しません。各コールはウィジェットを再作成します。状態（テキスト、選択、トグル）は**フレームループの外**、つまりアプリのモデルに置き、毎フレーム読みます。

## ImKit がどの位置にいるか

![ネイティブ Gallery 概要](images/gallery-overview.gif)

ImKit は、既存の Dear ImGui フレームの中で描かれる、テーマ付きウィジェットと複合部品の薄い層と考えましょう。

```
あなたのアプリ
  └── Dear ImGui コンテキスト + backend (GLFW/OpenGL, Metal, ...)
       └── あなたのフレームループ
            ├── ImGui::NewFrame()
            │    ├── 素の Dear ImGui ウィジェット
            │    └── ImKit のテーマ付きウィジェットと複合部品
            ├── ImGui::Render()
            └── 次のフレーム
```

ImKit のコールは**現在の** Dear ImGui コンテキストに対して働きます。コンテキストを-createし、描画したフレームを超えて生存しません。

## 誰が何を所有するか（所有モデル）

覚えるべきルールです。**ImKit は要求（リクエスト）を返すだけであり、あなたのデータを自分で処理しません。**

| もの | 所有者 |
|---|---|
| Dear ImGui コンテキスト、backend、レンダラ、フレームループ | **あなた（ホスト）** |
| フォントと font atlas | **あなた** |
| 表示・編集するデータ（ドキュメント、scene、media、graph） | **あなた** |
| 選択、Undo/Redo、永続化、設定 | **あなた** |
| `Theme` 値と適用タイミング | **あなた** |
| 画面に表示される描画 | ImKit（**あなたの**コンテキストとデータを受け与えられた場合のみ） |
| ボタン押下、ドラッグ、選択の結果 | **あなた**（返された要求経由） |

一文で言えば：**あなたはすべてを所有し、ImKit は描画と報告だけです。** ImKit が何かを返した場合——押されたボタンの ID、ドラッグされたクリップ、要求された編集——**あなたのコード**が意味と処理方法を決めます。

## ImKit が関わるフレーム、一行一行で

```cpp
// フレームループ外の、一度だけの実装:
auto theme = imkit::MakeTheme(imkit::ThemePreset::PrecisionDark);

// 毎フレーム:
imkit::ApplyTheme(theme, 1.0f);          // ImGui::NewFrame() の前
ImGui::NewFrame();

// UI を描画します。ImKit コールは単なる描画コールの延伸です。
if (imkit::Begin("Settings")) {
    imkit::ToggleButton("Verbose", &verbose);             // あなたの bool を読み書き
    imkit::ActionButton("Save", imkit::ActionVariant::Primary);  // 押下時 true
}
imkit::End();

ImGui::Render();
```

3 点に注目：

- `ApplyTheme` は**現在の**コンテキストに、`NewFrame` 前に一度だけ適用されます。
- ImKit ウィジェットはあなたが所有する値（`&verbose`）を**読み**、`ActionButton` が返す結果は**あなた**が処理します。
- `Begin`/`End` は ImKit コールのグループを括る描画スコープであり、寿命を持つオブジェクトではありません。

## 要点

- ImKit はあなたの Dear ImGui フレームの中で描画し、コンテキストを作成・所有しません。
- 毎フレームはゼロから再描画され、すべての状態はあなたのモデルが所有します。
- ImKit は要求を返す——その処理を行うのはあなたのコードです。
- テーマ適用は `NewFrame` 前に、`Begin`/`End` は必ず対応させてください。
