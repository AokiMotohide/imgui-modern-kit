Node Editor 刷新計画

シェーダーやジオメトリのノード、ゲームロジックのブループリント、汎用のデータフローを、1つのUI部品で組めるようにするための計画です。各項目を「現行の動作」と「提案」で並べています。実装はまだ行っていません。

実装状況

この計画の Phase 1〜5 を Version4.1 に実装しました。下の表は計画との対応です。以降の節は計画時の記述のまま残しています。

Phase状態計画から変えた点
1. 土台と不具合実装既定の見た目は Classic のままで、不具合の修正だけ既定を変えた（配線は型の色、Idle のステータス行は非表示）。Theme::node と .theme の node.* キーを追加
2. 接続のフィードバック実装循環の判定は今までどおりホストの canConnect に任せ、ライブラリは判定と LinkView::validity を描くだけ
3. ピン記号と配線実装DrawPinGlyph と PinChromeView を公開。ワイルドカードは型の判定を省き、使用不可のピンは理由つきで拒否する
4. ノード形状と状態実装NodeShape は Standard / Event / Compact / Variable / Boundary。Comment・Note・Subgraph は既存の NodeKind で見た目が決まる。Success は一瞬の点灯ではなく、Success の間だけ緑の枠
5. 操作・フック・プリセット実装プリセットの関数名は MakeNodeStylePreset。PushNodeStyle / PopNodeStyle は見送り（外枠は BeginEditor でまとめて描くため、途中の切り替えが効かない。ノード単位は NodeView::style を使う）

  • 値の欄とピンの表示の切り替え（ToggleValueSocket）
  • ノードを揺すって配線を外す操作（shakeToDisconnect）
  • 2ノード接続の既定キー（右クリックメニューと ConnectSelected だけ）

  • 見た目は、ImGui の描画データをソフトウェアで画像にして確認（Classic / Tinted / Flat / Gradient、ドラッグ中、形と状態、ライトとダークのテーマ）

結論

編集の仕組みはすでに実用水準です。足りないのは見た目の語彙（形・記号・状態）、つなげない・壊れている接続を見せる表現、他のimkit部品と同じ深さのカスタマイズの3つです。

維持編集の契約

型付きID、完全な編集要求バッチ、Begin/Update/Commit/Cancel、3段階の接続判定、動的・可変長ソケット、整列と自動配置、サブグラフ、プレビュー需要の通知はそのまま使います。

追加形・記号・状態

ノード形状を1種類から9種類へ、ピン記号を4種類から15種類＋配線ビーズ3種類へ増やします。記号はすべて新しく作り、DrawListで描くベクター図形にします。

新規接続の可否と異常の表示

ドラッグ中の候補の強調と減光、理由の表示、無効になった配線・循環・変換・必須入力の未接続を、色だけでなく線種と記号でも区別します。

見た目の方針

参考にするのは他ソフトの機能と情報の出し方です。形と色はimkitのテーマから作ります。製品名、アイコン、配色、特徴的な輪郭はそのまま使いません。

テーマが主役

ノードの面、枠、文字は他の部品と同じ意味tokenから作ります。カテゴリ色は薄く敷くだけなので、どのworldに切り替えても浮きません。

色だけに頼らない

接続できない、無効、変換、循環は、色に加えて線種（破線・点線）と記号（✕・⇄・↻）でも区別します。色覚の違いがあっても読めます。

記号は自作のベクター

ピン記号と配線ビーズは新しく設計し、ズームしても崩れないDrawList図形で描きます。画像やフォントは追加しないので、第三者素材の扱いは発生しません。

既定は控えめ

強い効果（グラデーション、光彩、流れ表示）は選択肢として用意し、既定では使いません。情報量の多い画面でも疲れない見た目にします。

接続のフィードバック

つなげない接続や、壊れた接続を見せる表現です。現行は接続をドラッグしている間だけ判定し、確定後の配線はすべて同じ見た目になります。

場面現行提案
ドラッグ中の候補すべてのピンに緑か赤の輪。プレビューは直線接続できるピンだけに光の輪。接続できないピンは25%、候補のないノードは本体ごと50%に減光。プレビューは本番と同じ曲線
近くの候補への吸着なし。ピンの上に正確に乗せる必要があるsnapDistance 以内の最も近い候補に吸着し、輪を大きくする
接続できない理由ImGui の tooltip に「Rejected: …」と英語で出るカーソルの横に理由のピル。文言はホストの reason をそのまま出す
接続できないピンに乗せたとき赤い点線の直線エラー色の細い点線と、ピンの赤い輪。離しても元の配線は変えない（現行と同じ）
変換が入る接続ドラッグ中だけ黄色の破線と下線確定後も配線の中央に変換ビーズ（⇄）。配線は出力から入力への型色グラデーション
あとから無効になった配線表示なし。型を変えても正常な配線のままLinkView::validity = Invalid でエラー色の破線、中央に ✕ ビーズ、受け側のピンを Error 記号。hover で理由を出す
循環ホストの canConnect で拒否するだけドラッグ中は「循環になります」。許可された循環の配線には ↻ ビーズ
必須入力が未接続PinRow のラベルに「*」が付くだけ。未接続でも警告は出ないRequired 記号（赤い点）。ヘッダー右に未解決の数
今の設定では使えないピンhidden で消すしかないUnavailable 記号。候補から外し、hover で理由を出す
複数入力の上限上限に達すると「Socket already occupied」長円の点が上限まで埋まり、ドラッグ中は「上限 4 本」と出す

判定そのものは今までどおりホストの責務です。ライブラリは ConnectionVerdict と、新しく追加する LinkView::validity と reason を描くだけで、配線を勝手に消したり直したりしません。

カスタマイズ

ノードエディタも、ボタンや表と同じ4段階で見た目を変えられるようにします。上の段ほど手軽で、下の段ほど自由です。

段ホストがすること使う型
1. テーマTheme を変えるだけ。.theme ファイルに node の項目を足せば、コードを書かずに world ごとに変わるMakeNodeStyle(theme)
2. スタイルNodeStyle の値とカテゴリ表を渡す。ノード・ピン・配線ごとに上書きするNodeStyle, NodeCategoryStyle, NodeView::tint, LinkView::color
3. スタイルの一時変更一部のノードだけ別のスタイルにするPushNodeStyle / PopNodeStyle
4. 描画フック部位ごとに描画を差し替える。false を返した部位は既定の描画に戻るNodeDrawHooks

描画フックは Skin と同じ流儀にします。関数ポインタと void* user を受け取り、ライブラリは所有しません。渡すのは位置、大きさ、ズーム、状態、解決済みの色で、ホストは公開DrawListに描きます。入力処理とIDはライブラリ側に残るので、フックを入れても選択、ドラッグ、接続の動作は変わりません。グローバルな登録先は作りません。

API案

既存の型の末尾に項目を足し、既定値では今の動作を保ちます。緑が新規です。名前は案です。

確認事項

実装に入る前に、次の4点を決めてください。

  1. ABI の扱い。NodeView・PinView・LinkView・NodeStyle の末尾に項目を足すと、構造体の大きさが変わります。node_editor は development API なので許容する案です。
  2. 既定の見た目。この案では既定値を現行と同じ（Classic）にし、新しい見た目はプリセットで選ぶ形にしています。既定を Studio に変えてもよいか。
  3. .theme ファイルへの node 項目の追加。テーマの書式が増えます。追加してよいか。
  4. 着手順。Phase 1 から順に進めるか、接続のフィードバック（Phase 2）とピン記号（Phase 3）を先に行うか。
