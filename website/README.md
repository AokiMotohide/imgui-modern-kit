# ImKit documentation site

This directory builds the bilingual Japanese/English documentation site with Astro and Starlight. The published manual is available in [Japanese](https://aokimotohide.github.io/imgui-modern-kit/) and [English](https://aokimotohide.github.io/imgui-modern-kit/en/). The root Japanese routes use the default locale; English routes are under `/en/`. `astro.config.mjs` sets the GitHub Pages project base to `/imgui-modern-kit/`. The repository workflow builds an artifact; publishing updates requires a manual dispatch with the `publish` input enabled.

## Build and update

Use Node.js 22.14.0, npm 11.9.0, and Python 3.10+ (standard library only), matching the site workflow and generation/check scripts. From this directory:

```sh
npm ci
npm run docs:generate
npm run check
npm run build
npm run check:site
```

If the default npm cache is not writable in a cloud workspace, set a writable cache path for the install, for example `npm_config_cache=/tmp/imkit-npm-cache npm ci`. Keep lockfile integrity checks and TLS certificate verification enabled.

`npm run verify` runs the same generation, Astro check, static build, and built-site checks in order. `npm run dev` starts a local authoring server. No external font download or secret is required.

`scripts/import-docs.py` moves selected bilingual consumer guides into routes, rewrites links, and copies only referenced still-image sources. Edit the maintained guide in `docs/`, then regenerate. Historical design notes and validation logs are not imported as broad public documentation. API pages are generated by `scripts/generate-api-reference.py`; review their source inventories and public headers after each change.

The API generator uses only `included: true` rows from `docs/reference/api-inventory.json`, verifies the pinned Dear ImGui revision against `include/imkit/native.h`, and reads the ImKit version from `CMakeLists.txt`. The Node Editor declarations come from `docs/reference/node-editor-api.json`; `docs/design-system-api.json` contains header/type metadata, not a full signature inventory. Do not change those descriptions into broader coverage claims. Declaration blocks are references rather than standalone call examples.

## Capture images

The checked-in GIFs in `docs/images/` are captures of the native ImKit Gallery or Node Editor companion. They are unchanged by the site build. The tracked PNG files in `src/assets/captures/` are still frames extracted from those GIFs for feature cards and paused media. The extraction choices are recorded in `scripts/extract-capture-posters.py`: the Components overview uses the final captured frame, the Timeline uses frame 2, and the other posters use frame 0. The original GIF is linked for explicit opening; the site does not embed it as an automatically playing image. The home showcase uses the shared `CapturePlayer`, which begins on a still frame and waits for a Play action.

Refreshing the posters is optional and requires Pillow in the Python environment:

```sh
npm run posters:extract
```

Pillow is not a website build dependency. Avoid redrawing, compositing, or presenting a website-rendered UI as a native Gallery capture.

## Examples and checks

Feature intros label examples as complete functions or host-state excerpts. Getting-started and Node Editor examples explain which context, state, provider, and request storage the application supplies. API signature listings remain visibly separate from copyable calls.

The representative integration and Node Editor snippets in both locales, the full Components settings-panel example, and the Themes, Workflow, Editor Suite, WindowFrame, and Icons examples were checked with GCC in C++20 syntax-only mode against the current public headers and pinned Dear ImGui checkout. The `BeginEditor` calls preserve the paired-call rules: `EndEditor` is unconditional, while `EndNode` follows a successful `BeginNode`. Any changed example that depends on new host state must be rechecked in that host context.

`npm run check:site` checks every generated local route and fragment, project base links, locale metadata, one main landmark per page, image alternatives, autoplay GIF usage, six feature cards, and that the generated native API code blocks contain every included signature and no excluded signature. Browser review should also query Pagefind with both `BeginEditor` and native-only names such as `TableGetColumnFlags` and `DragFloatRange2`; the signature blocks must be searchable.

## Pages workflow

`.github/workflows/docs-site.yml` runs on documentation changes and manual dispatch. It installs the frozen npm graph, generates the site content, validates and uploads `website/dist` as a Pages artifact. The `publish` checkbox defaults to false; deploy only occurs after an explicit manual dispatch with it enabled. Keep the repository's Pages source set to **GitHub Actions** for future deployments.

## ドキュメントサイトの更新

日本語を既定表示、英語を`/en/`配下に配置します。GitHub Pagesのproject base `/imgui-modern-kit/`は`astro.config.mjs`に設定済みです。更新後は上記の`npm ci`と`npm run verify`を実行してください。既存の日本語・英語資料から利用者向けのガイドを選んで移し、すべての履歴文書をそのまま公開しません。

画面画像は実際のGallery captureを静止画にしたものです。素材更新には任意のPillowが必要ですが、通常のnpm buildでは不要です。API宣言の出典と対象範囲は、inventoryとpublic headerを基準に保ちます。各コード例の完結した関数例とアプリ側の値を必要とする例を区別し、署名一覧を呼び出し例のように扱わないでください。

公開済みサイトの更新も、検証後にbuild artifactを保存し、`publish`を明示的に有効にしたPages workflowの手動実行で行います。

## ImKit 3.2 media

The hero uses a controlled, non-autoplay 60-second English film. `tools/capture_v32_media.py` records actual native UI backbuffers and makes final GIFs; `tools/render_v32_film.py` streams original motion graphics to FFmpeg and synthesizes the original score. Raw frames and audio stay in `out/`. Finished MP4 and poster are in `website/public/media/`. This film is a composition of native UI clips and original graphics, while every GIF in `docs/images/` remains a native capture. No narration or external music samples are used.
