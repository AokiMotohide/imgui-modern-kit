This page lists what 4.1 adds to the public API and where each piece lives. Every entry is a draw call or a plain value: the host owns state, textures and lifetime, and handles the returned request. Public structures grew at their end, so rebuild your application and every linked ImKit library with the 4.1 headers. Apart from the node editor, defaults are unchanged; see [Upgrading from 4.0](../../platform/migration-v4/#upgrading-from-40-to-41).

## Tile map for tiled displays

`show::TileMap` draws one cell per panel of a tiled display, such as LED wall cabinets. Tiles are coloured by group (the data port or power circuit that feeds them), each group is joined in `order` like its cables, and a dot marks the first tile. `highlightGroup` dims the other groups. The host gets the hovered and clicked tile and writes its own tooltip.

```cpp
#include <imkit/show.h>

const std::array<imkit::show::TileMapTile, 4> tiles{{
    {.column = 0, .row = 0, .group = 0, .order = 0, .label = "1-1"},
    {.column = 1, .row = 0, .group = 0, .order = 1, .label = "1-2"},
    {.column = 0, .row = 1, .group = 1, .order = 0, .label = "2-1"},
    {.column = 1, .row = 1, .group = 1, .order = 1, .label = "2-2", .missing = true},
}};
static int selected = -1;

imkit::show::TileMapOptions options;
options.highlightGroup = 0;                          // dim the other ports
const auto request = imkit::show::TileMap("wall", {.columns = 2, .rows = 2, .tiles = tiles}, &selected, options);
if (request.hovered >= 0) ImGui::SetTooltip("Port %d", tiles[request.hovered].group + 1);
```

## Adjustable control sizes

`Theme::layout` overrides the sizes that decide how tall controls are. An unset value keeps the density, so existing themes draw as before. `ResolveTheme` applies the layout after the density; call it after you change a token.

```cpp
auto theme = imkit::MakeTheme(imkit::ThemePreset::Graphite);
theme.layout.controlHeight = 34.f;     // taller controls
theme.layout.spacingY = 6.f;
theme.layout.checkHeightScale = 1.6f;  // checkbox height as a multiple of the font size
imkit::ResolveTheme(theme);
imkit::ApplyTheme(theme, 1.0f);
```

| Group | Tokens |
| --- | --- |
| Lengths (screen pixels) | `controlHeight`, `spacingX`, `spacingY`, `horizontalPadding`, `windowPaddingX`, `windowPaddingY`, `cellPaddingY`, `indent`, `scrollbar`, `grabMin`, `separatorTextPaddingY` |
| Component ratios | `checkHeightScale`, `toggleHeightScale`, `dialogPaddingScale`, `progressBarHeightScale`, `badgeExtraHeight`, `segmentedInset` |

`Metrics` gains the resolved values (`spacingY`, `windowPaddingX/Y`, `cellPaddingY`, `indent`, `scrollbar`, `grabMin`, `separatorTextPaddingY`, `parts`). Components that have no `Theme` (Checkbox, Toggle, StatusBadge, Segmented, dialogs, progress bars) read `parts` from the theme last applied to the context; `ThemeScope` restores the previous one. Theme files read and write `layout.*` keys (see [Theme file keys](https://github.com/AokiMotohide/imgui-modern-kit/blob/main/docs/architecture/make-your-own-look.md#theme-file-keys)); an unset token is not written.

## Sprites and progress thumbs

A `Sprite` plays a sheet of equally sized frames from one texture the host loads and owns. `Loop`, `Once` (then the rest frame) and `HoldLast` are supported. Under reduced motion it shows `restFrame`, and a rectangle outside the visible area is not drawn.

```cpp
imkit::SpriteSheet ball;
ball.texture = ballTexture;                       // host-owned
ball.sheetPixels = {256, 192};
ball.cellPixels = {64, 64};
ball.columns = 4;
ball.frames = 12;
ball.fps = 24.f;
static imkit::SpriteState state;
const bool animate = theme.motion.enabled && !theme.motion.reducedMotion;
imkit::Sprite("ball", ball, state, ImGui::GetTime(), {64, 64}, animate);
```

`SpriteFrameAt` and `SpriteFrameUV` return the frame number and its texture coordinates without a Dear ImGui context. `DrawSprite` draws one frame into any rectangle.

`ProgressTrackView::thumb` calls the host with the draw list, the track rectangle, the head position and the shown fraction, so a picture can ride the fill. It is called for a determinate track and for a running indeterminate one. `thumbHeight` reserves layout height above the track so the picture does not cover the header.

## PTZ control that draws only what the camera offers

`PtzView::capabilities` hides the controls a camera lacks. A pan-only head, a zoom-only lens or recall-only presets gets a smaller control; with nothing to offer it draws one line of text. Every field defaults to true, so existing code is unchanged.

```cpp
imkit::PtzView view;
view.capabilities.tilt = false;        // a pan-only head
view.capabilities.presetStore = false; // presets can be recalled, not stored
view.readoutText.pan = "+0.35";        // for devices that report normalised values
const auto request = imkit::PtzControl("camera", view, state);
```

With the default diameter the pad shrinks, down to 3.2 frame heights, to fit a narrow host instead of being clipped. New locale keys: `ptz.panPad`, `ptz.tiltPad`, `ptz.presetRecallHint`, `ptz.unsupported`. Details are in the [PTZ guide](https://github.com/AokiMotohide/imgui-modern-kit/blob/main/docs/components/ptz.md#capabilities).

## Node editor

The node editor gets a new default look and the parts to describe it. Full reference: [Node editor](https://github.com/AokiMotohide/imgui-modern-kit/blob/main/docs/components/node-editor.md).

| Area | Additions |
| --- | --- |
| Appearance | `NodeStyle::headerFill` (`Strip`, `Tinted`, `Flat`, `Gradient`, `None`), `headerTint`, `linkColor`, `linkArrow`, `highlightConnectedLinks`, `hollowUnconnectedPins`, `status`; `NodeView::category`, `tint`, `subtitle`, `glyph`; `Theme::node` and `node.*` theme keys |
| Presets and hooks | `MakeNodeStylePreset` (`Classic`, `Studio`, `Logic`); `NodeStyle::hooks` (`NodeDrawHooks`) replaces the drawing of backgrounds, title rows, sockets and links |
| Sockets | `PinView::role`, `container`, `flags`, `keyType`, `inspect`, `reason`; `DrawPinGlyph`, `PinChromeView`; flow links, capsule inputs, `pinSeat` |
| Wiring feedback | Candidate rings, faded incompatible sockets and nodes, snapping, a verdict pill; `LinkView::validity` and `reason` for existing links |
| Shapes and states | `NodeView::shape`, `diagnostic`; frame, group, note and subgraph cards; running, waiting, success, error, bypassed, disabled, cached, breakpoint and locked states |
| Panels | `BeginNodePanel`, `EndNodePanel`, `NodeView::hideUnusedPins` |
| Gestures | Alt-click breaks a socket's links, Ctrl-drag moves them (Cmd on macOS), double-clicking a link requests `EditKind::InsertReroute`, `ConnectSelected`; `Keymap::bypass` (Ctrl+B) and `collapse` (Ctrl+H) |
| Localisation | `EditorOptions::locale`; `EditorFrame::hoveredNode` |

## Ownership

| ImKit does | Your application keeps |
| --- | --- |
| Draws a tile map and returns the hovered and clicked tile | The tiles, the port assignment and the tooltip |
| Plays a sprite from the frame arithmetic | The texture, its lifetime and the clock |
| Draws only the PTZ controls the capabilities allow | The camera and what it reports |
| Applies layout tokens to the theme you pass | The theme file and its lifetime |
