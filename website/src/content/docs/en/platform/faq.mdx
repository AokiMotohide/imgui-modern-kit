## Does ImKit provide Dear ImGui?

No. Your application provides the Dear ImGui context, backend, renderer, font atlas and frame loop. When you build from source, set `IMKIT_IMGUI_TARGET` to your existing Dear ImGui target. See [Dependencies](../dependencies/).

## Does ImKit modify Dear ImGui?

No. ImKit uses only the public API of Dear ImGui and does not use `imgui_internal.h`. It does not fork, patch or recompile Dear ImGui.

## Can I use the prebuilt SDK?

Yes, when you have confirmed that the compiler, architecture, CRT, Dear ImGui revision, compile definitions and `imconfig.h` all match the SDK. If any of them differs, build from source. The steps and the ABI conditions are in [Getting started](../../getting-started/).

## Japanese text or the IME does not work.

Themes do not load fonts. Add the glyph ranges you need to your application's font atlas, and provide the platform IME callbacks that text input needs.

## Sizes grow every time I apply a theme.

Pass the scale only to `ApplyTheme` or `ThemeScope`. Do not also scale `Theme::metrics` yourself. A theme rebuilds the style from unscaled sizes.

## Can I run the Gallery from an embedded build?

When you embed ImKit as a subdirectory with the Gallery off, point it at your existing Dear ImGui target. A standalone build that includes the Gallery fetches the pinned Dear ImGui and GLFW revisions. See [Dependencies](../dependencies/).

## Is the number of API declarations the number of functions that were tested?

No. The number is the count of public declaration rows in the listing. A signature listing is not a call example, and it does not count how many rows had their interaction checked. Check the contract in each page and in the public header.
